8.1What Signals Are: the Lifecycle

A signal is generated, marked pending in the target's task_struct, and acted on only when the target is about to return to user mode. Pick a source and step through it.

    8.3Dispositions and Handlers

    For every signal the process chooses: default action, ignore, or run a handler. Set them, then send signals. SIGKILL and SIGSTOP refuse to change.

    process 4321: running

    execve() resets handled signals to default (the handler code is gone) but keeps ignored ones ignored. That's how nohup works.

    docker stop and PID 1

    The kernel ignores signals sent to PID 1 from inside its own namespace unless PID 1 installed a handler. A SIGKILL sent from the host's namespace still works. Time is sped up.

    elapsed0.0 s
    exit status–
    Connection: handlers run asynchronously, so they may only call async-signal-safe functions; signalfd turns signals into fd reads for an epoll loop (7.8).

    8.5Signals and Threads

    Handlers are shared by the whole process; masks are per thread. A process-directed signal goes to any one thread that doesn't block it. Here the process has handlers installed for SIGTERM and SIGINT.
