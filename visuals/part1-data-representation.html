1.1Bits, Bytes and Binary

A bit is a switch: 0 or 1. Binary is a positional system like decimal, but each position is worth twice the one to its right. Click the bits.

1.2Hexadecimal

Group bits in fours (nibbles). Each nibble is exactly one hex digit, 0–F. That's why two hex digits are always one byte.

Connection: memory addresses and dumps (/proc/self/maps, xxd) are written in hex because each pair of digits is one byte.

1.3Why a Byte Is 8 Bits

Each square is one value a code of that size can represent. Six bits fit uppercase letters and digits; ASCII needed seven; eight leaves room for everything else and won in 1964.

Pink square: 'A' = 65 in ASCII.

1.5Endianness

Same value, same addresses, same number of bytes. Only the order of the bytes in memory changes. Darker = more significant byte.

x86, ARM (as used), RISC-V: little-endian. Network protocols: big-endian.

Network byte order: why htons() exists

1.6Alignment

The CPU fetches memory in whole boxes. Data that fits in one box costs one trip; data that straddles a boundary costs two. Move the value and watch.

The red bar at byte 64 is a cache-line boundary. Crossing it means two cache lines; crossing a 4 KiB page boundary can mean two TLB lookups or two page faults.

1.7Padding: Build a Struct
