7.1File Descriptors

An fd is just an index into the process's descriptor table. open() always returns the lowest free number.

Try: close(0), then open again. The new file becomes fd 0, i.e. the program's new stdin. That's how shells redirect < file.

Connection: the table hangs off task_struct->files (4.2); its size limit is ulimit -n (RLIMIT_NOFILE), and hitting it gives EMFILE.

7.2Open File Descriptions: the Three Layers

    7.5Standard Streams and Redirection

    The shell redirects between fork() and exec() with open + dup2. Order matters. Step through each command.

      Connection: fds 0, 1, 2 are inherited from getty/sshd through every fork + exec (3.7); Ctrl+C and Ctrl+Z come from the TTY driver, not the shell (4.5).

      7.6Buffered vs Unbuffered I/O: Two Buffers

      Text goes from printf into the stdio buffer in your process, then via write() into the page cache, then to disk. The stdio buffer is scaled down to 24 bytes here.

      Connection: the page cache is a write-back cache (2.4, 6.7); fork copies the stdio buffer because it's ordinary process memory (COW, 4.9).

      7.7Blocking vs Non-Blocking I/O

      A blocking read on an empty socket puts the task to sleep on a wait queue. A non-blocking read returns EAGAIN immediately.

      task: R (running) socket receive buffer: empty socket wait queue: []
      Connection: sleeping in S is a voluntary context switch (3.5); the wakeup comes from an interrupt and softirq (3.4); regular files ignore O_NONBLOCK (disk waits are state D).

      7.8I/O Multiplexing: select/poll vs epoll

      select and poll make the kernel check every fd on every call. epoll remembers the interest list and keeps a ready list filled by wakeups.

      Deleting needs w + x on the directory, not on the file. With the sticky bit, only the file's owner, the directory's owner or root may delete. Root bypasses read/write checks but needs at least one x bit to execute.
