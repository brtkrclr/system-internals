Processes are isolated, so every conversation between them goes through the kernel. Pick a mechanism, fill a pipe, pass a file descriptor, race on shared memory, and follow a packet from the wire to read().

9.1Pipes and Named Pipes (FIFOs)

A pipe is a one-way byte stream with a ring buffer in the kernel. Scaled down here: 16 slots stand for the real 64 KiB. Make the writer faster than the reader and watch backpressure; then close an end.

Named pipe: mkfifo mypipe

A FIFO has a name (file type p), so unrelated processes can open it. open() blocks until the other end is opened too.

Connection: blocked ends sleep in state S on the pipe's wait queue (7.7); SIGPIPE is Part 8; the shell builds pipelines with pipe + fork + dup2 (7.5, Part 11).

9.3Shared Memory

Two processes map the same physical frames, usually at different virtual addresses. After setup there are no system calls and no copies, which is also why every race condition from Part 5 comes back.

The segment is a file in /dev/shm (tmpfs) mapped with MAP_SHARED (6.6).

Race: both processes do counter++ 1,000 times

Simulated: each increment is read → add → write, and the scheduler may switch processes between any two steps (here with a fixed probability).


  

  
Connection: process-shared mutexes work because futexes can be keyed by the shared physical page (5.3); the mapping is a VMA pointing at page-cache pages of a tmpfs file (6.4, 6.7).
